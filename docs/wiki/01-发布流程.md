# 发布流程

## 一条命令

```bash
npm run release -- vX.Y.Z
```

可选参数：

| 参数 | 作用 |
| --- | --- |
| `--dry-run` | 走完类型检查、构建、打包与全部断言，只跳过创建 Release，并打印将要执行的命令与包内容 |
| `--notes <文件>` | 用自定义文案替代自动生成的说明 |
| `--allow-dirty` | 允许工作区有未提交改动（会破坏「产物对应某个提交」的假设，慎用） |

脚本文件：`scripts/release.mjs`，零第三方依赖，只用 `git`、`gh`、`zip`、`zipinfo`。

## 执行顺序

1. **前置检查**：版本号格式、`gh`/`zip` 可用、从 `origin` 解析仓库 slug、HEAD 是否已在远端、tag 与 Release 是否重名。
2. **构建**：`tsc --noEmit` → 删掉旧 `dist/` → `vite build`，并从构建输出里解析每个产物的体积与 gzip。
3. **打包**：`zip -r -X <临时目录>/cduyzh.github.io-dist-<短sha>.zip dist -x '*.DS_Store'`，保留 `dist/` 这一层目录，解压即为站点根目录。
4. **发布**：`gh release create <tag> --target main --title ... --notes-file ... <zip>`。
5. **校验**：`gh release download <tag>` 把资产拉回本地，与源文件比对 SHA-256，一致才算成功；临时目录随后清理。

说明文案默认自动生成：源提交、Node/Vite 版本、产物文件数、各 chunk 体积表格、使用方式。

## 五道守卫及其由来

| 守卫 | 不加会怎样 |
| --- | --- |
| tag 必须形如 `vX.Y.Z` | 出现无法排序的发布名 |
| HEAD 必须已推到 `origin/main` | `gh release create --target` 指向不存在的提交，发布失败或指向错版本 |
| 工作区必须干净 | 构建取自工作区、tag 指向提交，两者不一致会发出对不上的包 |
| zip 必须含 `dist/` 的每个文件且含 `index.html` | 实际发生过：多写一个 `-x '*.html'` 就打出了没有入口页的包 |
| 校验只走 `gh release download` | `curl` 直连 CDN 下载链接在本机返回 `http=000`，会被误判成发布失败 |

## 手工兜底

脚本不可用时按上面五步手敲，注意两点：`zip` 的排除项只能写 `*.DS_Store`；校验用 `gh release download`，不要用 `curl`。
