# 已知缺陷

按严重度排列。每条给现象、证据、建议处置。

## 1. Pages 发布源与 CI 不一致（阻断线上更新）

**现象**：推送到 `main` 后 Actions 两个作业都是绿的，线上站点却不更新。

**证据**（2026-09-16 实测）：

- `gh api repos/cduyzh/cduyzh.github.io/pages` 返回 `build_type: legacy`、`source: {branch: main, path: /}`，而 `.github/workflows/deploy.yml` 走的是 `upload-pages-artifact` + `actions/deploy-pages`，要求 Source = GitHub Actions。
- `https://cduyzh.github.io/` 的 `last-modified` 就是那次部署时间，内容却是**仓库源码版** `index.html`（引用 `/src/main.tsx`，浏览器里必然白屏）。
- 绑定域名 `https://www.cduyzh.top/` 仍停在 `last-modified: 15 Sep 2026` 的旧构建（入口 970 kB 单包、无分包）。

**处置**：仓库 Settings → Pages → Source 改为 **GitHub Actions**，然后重跑一次 workflow。这是生产配置，需人工操作；**不要**反过来把 `deploy.yml` 改成提交 `dist/` 到分支的旧式做法。

**验证是否生效**：拉线上 `index.html` 比对 `<script src>` 的 chunk 哈希与 `last-modified`。注意 `via: 1.1 varnish` + `x-cache: HIT` 说明 Fastly 还有一层 600 s 缓存，刚部署完取到旧内容属正常。

## 2. 工作区里有一版未提交的 3D 改写（待决）

`src/components/SpatialCanvas.tsx` 被并行会话整体换成单一 `THREE.Points` 粒子场（桌面 6000 / 移动 2500 个），`transmission`、`RoomEnvironment`、`MeshPhysicalMaterial` 全部移除。

- 代码本身可编译可构建，console 零报错。
- 但逐屏截图显示粒子铺满全屏并压在 hero 标题与分区标题上，可读性与克制感倒退，且与已发布的 `v0.3.0` 冲突。
- 同一批未提交改动里还有 `.veil` 不透明度 0.86→0.78、新增 `SectionDivider`、若干 CSS keyframes、`VisualBreak` 重写——这些看着是无害打磨。

**处置**：先确认粒子场是不是有意方向。若不是，只回退 `SpatialCanvas.tsx`，其余照常提交。

## 3. 锁文件冗余

仓库同时存在 `package-lock.json`（CI 的 `npm ci` 只认它）与 `bun.lock`，工作区里还有未跟踪的 `pnpm-lock.yaml` 和 `pnpm-workspace.yaml`。后者内容是 pnpm 交互式命令留下的半成品：

```yaml
allowBuilds:
  esbuild: set this to true or false
```

**影响**：三套锁文件必然互相漂移；`pnpm-workspace.yaml` 一旦提交会把仓库标记成 pnpm workspace。

**处置**：确定唯一包管理器（当前事实是 npm），删掉另外两套。

## 4. 根目录遗留临时改写脚本

`modify.js`、`modify.cjs` 用绝对路径读文件再做字符串替换来改 `SpatialCanvas.tsx`，是并行会话的过程产物，未跟踪。

**处置**：确认后删除，不要提交。

## 5. 三个组件已无引用

`src/components/HeroThreeCanvas.tsx`、`TechSection.tsx`、`Preloader.tsx` 均被 0 处引用。Rollup 从入口可达图打包，所以它们**不进产物**，只是死代码，会误导阅读与后续改动。

**处置**：确认无保留意图后删除。

## 6. 体积告警

- `SpatialCanvas-*.js` 543 kB 超过 Vite 默认 500 kB 阈值。它是异步 chunk，不在首屏关键路径上，可只做说明：把 `build.chunkSizeWarningLimit` 提到 600 以免每次构建都刷警告。
- 入口仍有 455 kB（gzip 142 kB）：`react-dom`、`motion`、`lucide-react` 首屏即需，继续拆收益有限。若要进一步压，方向是按需引入 `motion` 的子入口而非 `motion/react`。

## 7. 已修复项（留档）

- `package-lock.json` 原先不含任何 `resolved`/`integrity` 字段，`npm ci` 直接 `EUSAGE` 失败，CI 靠 `npm ci || npm install` 兜底。已在 `2bda95d` 修复，并把 93 个平台二进制条目指向 `registry.npmjs.org`（本机镜像是 npmmirror），抽查 4 个 tarball 的 SHA-512 与官方源一致。
- 代码分割前入口单包 990 kB / gzip 277 kB，见 [视觉系统](02-视觉系统.md)。

### 滚动停驻与降级约定

实现位于 `src/hooks/useScrollScene.ts`、`Hero.tsx`、`About.tsx` 及 `src/index.css`。以下距离是当前源码配置值：

| 场景 | 滚动区间 | 降级条件 |
| --- | --- | --- |
| Hero | 桌面 `260svh`；移动端 `215svh` | 视口高度不大于 `600px` 或启用减少动态效果时，使用静态自然流 |
| About | 桌面 `175svh` | 移动端、视口高度不大于 `700px` 或启用减少动态效果时，使用静态自然流 |

- `sticky` 停驻区与 `useScroll` 的 `offset: ['start start', 'end end']` 对齐，进度映射到元素的 `scale`、`translate` 与 `opacity`；上下滚动均可 scrub，返回前一位置时恢复相应视觉状态。
- 统一通过 `useTransform(scrollYProgress, value => value)` 派生 JavaScript 进度，再映射各元素，避免原生滚动时间线下 `opacity` 区间与 `transform` 的进度发生分歧。
- 逐帧样式更新使用 MotionValue，不逐帧调用 React `setState`。首屏动作区仅在越过可访问性边界时更新状态，已淡出的链接退出 Tab 顺序。
- 静态模式将内容恢复到正常文档流，保留标题、项目展示与访问入口，不用透明或屏外内容代替动画降级。

```bash

npm run preview -- --port 3101

# 终端 2：通过 withManagedBrowser() 复用本轮受管浏览器
```

脚本支持以下环境变量：

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
